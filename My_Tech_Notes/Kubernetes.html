. K8S Architecture

.. K8S Architecture: the Control Plane

The control plane is the control tower of a K8S cluster

  • API component: exposes the K8S API, each entity has an API endpoint.
    Kubernetes exposes a REST interface.
    It is a containeraised application, run as a pod.
    It handles requests from the user and from inside the cluster.
  • etcd: a key-value store. It saves all data about the state of the cluster.
    Only the Kube API server can communicate directly with etcd.
  • Scheduler: identifier new pods and assings them to a node
  • Controller Manager: a loop that continuously checks the status of the cluster, to make sure things are running properly.
    If a worker node breaks, it is replaced with a new worker node.
  • Cloud Controller Manager : lets you connect the cluster with a cloud provider API
    So you can use cloud resources from AWS, GCP, etc.
The control plane nodes are hidden from kubectl if you run the K8S by a Managed Cloud Provider.

.. K8S Architecture: the Worker Nodes

In the airport, the Worker nodes are like the busy terminals, there are a minimum of three worker nodes.
The worker nodes are where POD(s) are scheduled and run.
Each worker node has three components:
  • Kubelet: an agent that runs on every worker node, it makes sure that the containers in a pod are running and healthy
    It communicates directly with the API server in the control plane, looking for newly assigned POD(s)
  • Container Runtime: when a Kubelet is a assigned to new pod, it starts a continer using Continer Runtime Interface (CRI)
    CRI enables the Kubelet to create container with the engines: containerd, etc.
  • Kube-proxy: it makes sure that POD(S) and services can communicate with other POD(s) and services, on nodes and in the control plane.
    Each kube-proxy communicates directly with the Kube-API-server.

. Theory

.. Theory: Containers

A technology that bundles: the code for an application, and the configuration to run the code itself, in one unit.
Virtualized instances of operating system kernels. A file stored in a container, example has path: /tmp/foo.txt, it is actually a file, with a longer path, in your computer.
In a VM, the file is stored in the VM hard-disk, your computer does not known anything about that file.

Dockerfiles create Docker images through layers of instructions. With docker, as long as your computer supports Docker, your app can run on anything.
Docker runs on a container runtime called containerd.

Docker at scale can be a challenge. Advantages of containers over virtual machines:

  • Containers are portable
  • They use less CPU and memory than VM(s)
  • Self contained, they run in seconds
  • Allows to quickly create replicas of an application, to elastically scale up and down.

What is cloud native?
Cloud native technologies allow to build and run scalable applications in public, private and hybrid clouds.
Containers, service meshes, microservices, immutable infrastructure, and declarative APIs simplify this approach.

Alternative: Cloud native technologies are open-source projects designed to let-technologists use cloud computing services to automatically deploy and scale applications.

Other CNCF open-source projects: Helm, Prometheus, Linkerd.

.. Theory: Pods

kubectl apply -f pod_info_deployment.yaml
The smallest unit of computing that K8S can run.
They group similar containers into a logical unit.
All POD(s) of the same kind have the same IP address and move together.

PODs are scheduled in a K8S Kubelet, or node.

K8S deployments,
POD(s) are discovered by Services. Services make POD(s) discoverable.
Services provide a single IP address and a DNS for a group of related POD(s).

Ingresses and Ingress controllers make your app internet accessible.
They are HTTP reverse proxy that allow that allow the external world to reach the POD(s) of the cluster.

.... Theory: Pods: Deployment: Deployment Object

POD(s) can be deployed using: Deployment script.
No downtime upgrade. It is possible to deploy a new version without interrupting the current one. K8S makes sure that the new POD(s) are running before shutting down the old one.

... Theory: Pods: Running Stateful Workloads

How do you handle a data storage in K8S?
  • Connect the application to a database , independent of your cluster, outside.
  • Kubernetes persistent volumes: a data storage that exists in the cluster and remains event after a POD is destroyed.
    You can use a stateful set, to make sure your updated application can communicate with the same volume as the previous POD.

.. Theory: Services

Kubernetes services:
  • Load balancer
  • Node port
  • Cluster IP
A Kubernetes service is a load balancer that directs traffic from the internet to the Kubernetes pods.
The K8s service has a public and static IP address. The inner pods and IP addresses can change, but the static address of the K8S service IP is static.
The service has a key called spec:selector:app it must match with metadata:labels:app of the yaml that deploys the pod.

Resource Management for Pods and Containers

  • Use computational resources to mine cryptocurrencies
  • Cause a distributed Denial of Service or DDOS attack
Use security settings.
