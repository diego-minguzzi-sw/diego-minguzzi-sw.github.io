ros2 bag record --topics /my_number
Play back a bag, in infinite loop: 
ros2 bag play -l rosbag2_2026_08_14-17_31_08/

ROS2 Run

To run a node renaming the node name to my_node2:

ros2 run my_cpp_pkg my_cpp_node --ros-args -r __node:=my_node2

Runs number_publisher. The topic named number becomes my_number 

ros2 run my_py_pkg number_publisher --ros-args -r number:=my_number

ros2 run my_cpp_pkg number_subscriber --ros-args -r number:=my_number

# The same CLI argument can rename a service, for example:
ros2 run my_cpp_pkg number_publisher --ros-args -r reset_counter:=my_reset_counter

# Load a parameters file before running a node.
ros2 run my_cpp_pkg number_publisher  --ros-args --params-file ${HOME}/skunk_ros_ws/src/my_cpp_pkg/param/number_params.yaml

ros2 run my_cpp_pkg number_publisher  --ros-args __node:=num_pub2 --params-file ${HOME}/skunk_ros_ws/src/my_cpp_pkg/param/number_params.yaml

# Overrides the node name and loads the parameters file.
ros2 run my_cpp_pkg number_publisher  --ros-args -r __node:=num_pub2 --params-file ${HOME}/skunk_ros_ws/src/my_cpp_pkg/param/number_params.yaml

TF (TransForms)

Make sure that RViz and additional packages are installed:

  sudo apt install ros-jazzy-tf2-tools
Example URDF files are available in the package urdf_tutorial.
Example of how to launch RViz with a model: 

  ros2 launch urdf_tutorial display.launch.py model:=/opt/ros/jazzy/share/urdf_tutorial/urdf/07-physics.urdf
  • A link is a rigid part: a solid part without articulation
  • TF: frames
Coordinate systems follow the right-hand rule in ROS:
  • X points forward
  • Y points on the left
  • Z points up
In RViz, arrows represent the relationships between links (the rigid parts).
  • Link: a rigid part of the robot: define visual aspects, inertial and collision properties
  • Frame: the origin of a link, called Axis in RViz, the reference frame of a link
  • TF: the relationship between two frames, that is: the relationship between the parent link origin and the child link origin.
    TFs define how links are connected and how they move between each other
In order to show the TF tree: 

  # Export a Ghostview and PDF representation of the TF tree:
  ros2 run tf2_tools view_frames

Quaternions and RPY

https://eater.net/quaternions Videos

The Fixed frame RPY

There are several ways of applying Euler angles.
The one which ROS 2 adopts, is called fixed (or static) frame RPY.
This means that the three individual rotations are applied to the original, unmoving coordinate axes.
This is contrary to relative frame, where rotations are applied to the coordinate axes that get transformed by preceding rotations.

Think in RPY, then Convert to Quaternion

Think in RPY, then Convert to Quaternion
Example of applying a rotation as a quaternion:

  #include 
  ...

  tf2::Quaternion q_orig, q_rot, q_new;

  q_orig.setRPY(0.0, 0.0, 0.0);
  // Rotate the previous pose by 180* about X
  q_rot.setRPY(3.14159, 0.0, 0.0);
  q_new = q_rot * q_orig;
  q_new.normalize();

Chained Rotations

Three consecutive elemental rotations are sufficient to reach any target frame. Wikipedia
Three elemental rotations can be
  • Extrinsic: rotations about the axes x, y, z of the original coordinate system, which is assumed to remain motionless
  • Intrinsic: rotations about the axes of the rotating coordinate system X, Y, Z, solidary with the moving body, which changes its orientation with respect to the extrinsic frame after each elemental rotation
