The architecture must support what is expected from software (10): functional requirements, attributes of the solution, constraints coming from different places.
Many requirements came from the architecture context:
  • Stakeholders:
    • Users are: end-users (user-experience, performance, functionalities) and administrators (users management, sys configuration, backup and recovery)
  • Business and technical environment. Tech environment: technologies already used by the company
  • Architecture and Agile
  • Domain Driven Design: in order to make the proper design decisions, you have to understand the domain first.
    The concepts in the code must be named after the entities that are part of the ubiquitous language
SOLID and DRY principles
  • Single Responsability: (17) if a function has an AND in its name it is violating the Single Responsability Principle. If a function has comments marking different sections, violates this principle as well.
  • Open for Extension, Closed for modification.
    OCP: Open Close Principle (27).
  • Liskov substitution principle
  • Interface segregation: no client should be forced to depend on methods it does not use (20).
  • Dependency Inversion: high level modules should not depend on low level modules, rather on interfaces
Coupling: how strongly one software unit depends on another software unit. If a modification to a sw unit means that the other must be changed as well (26).
Cohesion: how strongly the elements of a sw unit are related.
  • High cohesion, low coupling: a class method always use the same fields, a few calls to a few classes
  • Low cohesion, high coupling: a class has a low of fields, every method uses a few of them; many calls to other classes
(21)

Architectural Styles

  • Stateful services: the service keeps track of the session state
  • Stateless: two requests, with the same parameters return the same results, if data are the same. REST: all the state needed to process a request must be trasferred within it.
Microservices: an application is split into loosely coupled services that communicate using lightweight protocols (38).
