Managing logs with syslog

Hackers want to damage your logs, to hide their tracks, then they get access to your data.

syslog is installed by default and configured in every Linux system.
journad is replacing syslog, but even in systems that have journald, syslog is running.
syslog logs into /var/log.
Ubuntu uses /var/log/syslog

Usually the syslog files should have read and write unallowed to regular users.
Syslog contains the general information about our system. The /var/log directory contains log from other services and applications.

Periodically send log files to a centralized log server. All logs in one place.

Logs retention and rotation

Log rotation is configured in /etc/logrotate.conf

RSysLog

There is rsyslog : remote syslog.
It allows you to store the log files locally and remotely.

How to configure it?
In /etc/rssyslog.conf 

# provides TCP syslog reception
#module(load="imtcp")
#input(type="imtcp" port="514")
If we uncomment those lines, the machine becomes a rsyslog server, that can receive rsyslog messages from clients. (better to use TCP syslog reception)
RSyslog haas not authentication, there must be a firewall to allow access to that port from selected client IPs.

How to set the current machine as a rsyslog client that sends log messages to another machine? It is possible to use ssh tunnel to access that port.
With ssh tunnel you get authentication and encrypted communication.
In /etc/rssyslog.conf add :
*.* @@172.16.10.100:514
Now, it is both storing log messges locally and sending them through the network.

Moreover

  • Setup a backup strategy
  • Consider logging not using text files, but for example database entries. The text file must be stored all at once in memory.

Managing logs with journald

Part of SystemD. Official name is System D Journal.

Journald is considered easier to work with, than syslog.
In syslog, all log messages are stored as text files, easy to manipulate and remove log entries, with root priviledges.
In journald, all log files are stored in binary files. They are harder to modify with an editor. Better performance , better tools to search.

journalctl # Lists the log messages journalctl -n 20 # Give me the last 20 lines, similar to tail. journalctl -f # Show me the last few lines.

Filtering

journalctl -p warning -f # Show priority warning and below. Follow the log. journalctl --since="2026-09-20 00:00:00" --until="2026-09-20 17:04:00" # Filtering by datetime. journalctl --since="2026-09-20 00:00:00" --until="2026-09-20 17:04:00" -p warning
Suppose I filter messages and I find that a service raises errors. Suppose it is the Samba daemon. In journalctl everything is a unit. Get extended messages and explanation.
journalctl -xau smbd journalctl -xau firewall
Priorities are between 0/"emerg" and 7/"debug"

Storing logs to the disk

Journald keeps log entries in memory: most of the distros rely on sylog to store the logs on the disk.
If journald finds that the directory /var/log/journal exists on the disk, it will store its logs into it. The directory must have the proper permissions.
drwxr-sr-x+ 3 root systemd-journal 4096 Aug 20 2025 journal
In the file /etc/systemd/journald.conf, set
[Journal] Storage=persistent
Means: if the folder does not exists, create it, with the right permissions.
