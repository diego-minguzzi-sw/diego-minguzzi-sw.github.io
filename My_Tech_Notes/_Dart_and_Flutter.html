  }

Function names are lowerCamelCase (151).
Parameters / arguments. A function parameter is a name and a type defined as an input for a function. An argument is the actual value passed to a function (153).
Optional arguments
  String fullName(String first, String last, [String? title]) {} // title is an optional argument.
Functions do not need to be defined before they are used.
Named parameters
Dart allows you to name parameters.
  bool isWithin(int value, {int minValue = 0, int maxValue = 10}) { ... } 
  // isWithin() must be called with the syntax: isWithin(15, minValue: 10, maxValue: 20)

A named parameter is also an optional parameter if it has a default value.
  // value is named and required.  All other named parameters are optional.
  int valueWithinRange2({required int value, int min = -1, int max = -1}) { ... }
If the function signature it too long, adding a comma after the last parameter lets the IDE format it vertically (160).
Pure functions have no side effects (163)
Dart recommendation for functions:
    Use noun phrases for pure functions, e.g. averageTemperature() instead of getAverageTemperature() (164) Use verb phrases for functions with side effects, for example updateDatabase() or printHello() Do not repeat parameters in the function name cube(int number) instead of cubeNumber(int number)

(173) Closures. Note: 
Function countingFunction() {
  var counter = 0;
  return () {
    counter++;
    return counter;
  };
}
Each anonymous function returned by countingFunction() gets it own instance of counter (175). So, an object that has just a method can be created as an anonymous function with its own state, given by the closure.

.... Interfaces

Dart has single inheritance; however, multiple interfaces can be implemented (341).
Note: (333) business logic = domain logic = business rules
Mixing stable code with unstable code causes the stable code to become unstable.
Code against interfaces, not implementations. (335)
In Dart, interfaces are abstract classes. When creating a concrete class that implements an interface, use the keyword implements instead of extends (336).

Every class implicitly defines an interface containing all the instance members of the class and of any interfaces it implements.
If you want to create a class A that supports class B’s API without inheriting B’s implementation, class A should implement the B interface. (341) If SomeClass implements AnotherClass, then SomeClass must provide its own version of all methods and variables in AnotherClass.
Fields and methods must be overridden using the annotation override (342).

In Dart, the common pattern is an abstract class that has a factory method that creates object of concrete classes (338).
An alternative is a service locator (338).

.... Handling nullable types

Type promotion (243) the compiler can promote a nullable to non-nullable by analyzing the code and performing flow analysis.
  String sayHello({String? name}) => 'Hello ' + (name ?? 'Mr.Nobody'); // If-null operator
  
  int nullAware(int? value, {int optionalNewValue = 0}) {
    var result = value;
    result ??= optionalNewValue; // Null-aware assignment operator. result is assigned if it is null.
    return result;
  }

  String? name;
  print('name?.trim(): ${name?.trim()}'); // Null-aware access operator a.k.a. null-aware method invocation.

(359) Dart is a single threaded language: Dart is based around concurrency on a single thread.
Parallelism versus concurrency (360).
  • Parallelism: multiple tasks run at the same time on multiple CPUs
  • Concurrency: multiple tasks on the same CPU core.
The problem with parallelism is access to shared resources (362).
In Dart each thread runs in an isolate (362): each isolate has only a thread. However, the program can create multiple isolate(s): they exchange messages with each other.
Event loop, microtask and event queue: Dart has an event loop; the loop has two queues: a microtask queue and an event queue (365).
The microtask queue is used internally, the event queue contains keystrokes, UI events, etc.
  • Synch tasks are run immediately, they cannot be interrupted
  • If a task agrees to be postponed, it is put in the event queue
  • If there is no synch task, the microtask queue is checked, for tasks to be executed. At any time, microtasks have priority over events.
  • If there are no synch tasks and the microtask queue is empty, the event queue is checked: if so, it is treated a a synch task

.... Futures

A future is a promise to give you a value later.
A Future can have any of the following states: Uncompleted, Completed with error, Completed with value (369).
Example of async and await (373).
Future main() async {
  try {
    final result = await Future.delayed(Duration(seconds: 1), () {
      return 42;
    });
    print('${DateTime.now()} result: $result');
  } catch (error) {
    print('${DateTime.now()} Error detected $error');
  } finally {
    print('${DateTime.now()} Operation finally completed.');
  }
}
