If a name begins with an uppercase letter, it is exported to other packages, otherwise the name is only visible in that package.
Camel case is the preferred way.

Variable declaration

Multiple variables can be declared in the same declaration:

Short variable declaration: name := expression : It is preferred for local variables.

It can be used for local variables.

A variable can be created using the built-in function new(). new(T) creates an unnamed variable of type T.

Scope

The variable lifetime lasts until the variable becomes unreachable (35), then it is garbage collected. The variable lifetime does not depend on whether the variable is allocated with new or with var.
Synctactic block: a sequence of statements enclosed in braces: a named inside a synctactic block is not visible outside that block.
The generalization of a synctactic block is a lexical block.(46)
A program can contain multiple declarations of the same name as long as each declaration is in a different lexical block. Lexical blocks can be nested, so a declaration may shadow another.
(47) A for loop creates the explicit block of the loop body and the implicit block that encloses the variables declared in the initialization cause. A variable declared in the implicit block has a scope: the condition, the post statement and the loop body.

Note: if and switch statements can create implicit blocks: 

  if x := f(); x < 0 {
      // ...
  }
At package level all declarations have the same scope, so it is possible to create mutually recursive types (48)

Error handling in Go

(128)
  • In case there is one possible way to fail, failure is indicated as the last return value, usually called ok>
  • In other cases an error may need an explanation: in such cases, the type of the additional result is error
  • The error is an interface type
  • In go there is no exception mechanism
Error handling strategies:
  • Propagate the error directly to the caller
  • Construct a new error, for example using fmt.Errorf() error messages are all lowercase, separated by semicolons
  • Retry the operation, possibly with a delay between the operations, before giving up
  • Log the error and continue, for example logging or printing to stderr
  • Ignore the error completely
(131) In go, after checking an error, failure is usually dealt with before success. Logic for success is not indented within an else block but follows at the outer level.

End of File (EOF)(131) there is a distinct error, io.EOF to signal any error caused by trying to read beyond the end of a file or stream.

Deferred function calls

(143) A defer statement is an ordinary function or method call prefixed by the keyword defer.
The function and the argument expressions are evaluated when the statement is executed. The actual execution is deferred until the function that containes the defer statement has finished, whether normally or by paniking. The right place for the defer is immediately after the resource us acquired.
Any number of calls may be deferred: they are executed in the reverse order in which they were deferred.

Panic

(148) Run-time error cause panic. A panic causes the program to crash, it is not an exception.
The convention is that the program panics in case an assertion fails.
The panic( s string) function exists.
Panic is not exception: the program panics in case a logical inconsistency is detected.

Recover

If the built-in recover function is called is called within a deferred function, and the function containing the defer statement is panicking, then recover ends the current state of panic and returns the panic value.

The fields and methods of a type inhabit the same name space, it is not possible to declare a method and a name with the same name.
On the other hand, a different type, example Path can have a method called Distance.

For example:

Not that Path is a named slice type, yet we can define methods on it.
So, in Go, methods can be associated with any type.
The receiver can be a pointer in case the method modifies the type fields, otherwise modifications are lost.

Interfaces

(174) An interface type describes the set of methods that a concrete type must possess to be considered an instance of that interface.

(171) In Go, interfaces are satisfied implicitly.
Simply possessing all methods is enough to adhere to an interface.
A concrete type satisfies the exact representation of its values and its methods.
(172) An interface is an abstract type: it reveals some method.
Given an interface, only what it can do is known. Example: io.Writer is an interface.
In Go, interfaces have names like: Writer, Reader, Closer (something that can be closed), etc.
It is important the fmt.Stringer interface, the method is. String() string.
Given the existing Reader and Writer interfaces, it is possible to use the interface embedding and declare a new interface like below, reusing existing interface declarations: 

type ReadWriter interface {
    Reader
    Writer
}
In interfaces, the order does not count.

(175) A concrete type is a particular interface, means that the type satisfies all methods of that interface.
An interface is like a data type. Example: 

var w io.Writer
(175) An expression can be assigned to an interface if its type satisfies that interface. The Empty interface is: 
interface{}
(176) we can assign any value to the empty interface. Trick: we can assert at compile time that a given type implements an interface, for example using:
var _ io.Writer = (*bytes.Buffer)(nil)  // *bytes.Buffer must satisfy io.Writer

(182): an interface value has two components: a dynamic type and a dynamic value. An interface keeps track of the type of its assigned object, if any.
A call through an interface uses the dynamic dispatch (183).
Interface values are equal if they are either: nil, or same type and value. Beware some types, like slices, cannot be compared.
(183) A variable of type interface contains the dynamic type and the dynamic value. It knows the actual type it is referring to .
(184) The verb percentage T reports the dynamic type of an interface. Type assertions (205)
A type assertion is an operation applied to an interface value.
Syntactically a type assertion looks like 

x.(T)
where x is an expression and T is the asserted type. (203)
  • If T is a concrete type and x type is equal to T; if the fails the operation panics
  • If T is an interface type, then the assertion check is x satisfies T, the valued is casted to the interface T
If the result of x.(T) is passed to two values, then the first is a reference and the second is the ok boolean.
A typical pattern is: 
if w, ok := w.(*os.File); ok {
    // ...use w...
}

Type switches

Interfaces are used in two distinct styles (210).
  • To create types that express concepts and theirs similarities, hiding the representation, e.g Reader, Writer, Stringer, etc.
  • To exploit the ability of interface to hold values of different concrete types ( a union of types ). Type assertions are used to discriminate among those types dynamically

Type switch (210). 
switch x.(type) {
    case nil:
    case int, uint:
    case bool:
    case string:
    default:
}
Extended form of the type switch statement: 
switch y := x.(type) { /* ... */ }
y is used by the cases to access the actual value. The common pattern is hiding x:

Go routines and channels

(225) A channel has a type, called the element type. To create a channel: 
ch := make(chan int) // ch has type 'chan int'
make() creates a reference to a channel. (225) 
    ch <- x   // a send statement
    x = <-ch  // a receive expression in an assignment statement
    <-ch      // a receive statement; result is discarded   
    close(ch) // closes the channel.
A buffered channel is created with a make statement like: 
    ch = make(chan string, 3) // Channel with a buffer of three elements.
len() and cap() can be applied to a buffered channel. A Go routine leak occurs when (237):
  • No go routine is draining from a channel, that for example has capacity one
  • More than one go routine is trying to sent to that channel
When the program exits, there are go routines blocked waiting for the channel to become available for the send.
(238) A synch.WaitGroup is an atomic counter that can block until the counter reaches the zero.
Check page: 238: one additional go routine is created to wait until a set of go routine terminate, to close the channel.

The select statement on one or multiple channels. Example:

select {
  case <-ch1:
    // ...
  case x := <-ch2:
    // ...use x...
  case ch3 <- y:
    // ...
  default:
    // ...
}
Each case can specify a send or a receive operation, as long as it is ready to proceed.
It is possible to send a cancellation event to one or more go routines (251). Remember that when a channel is closed, all receiving go routines receive the zero for that data type.
  • Define a done channel
  • When it is time to close all, close the done channel
  • All interested go routines can check the done channel with a select, normally no event is received, but when the channel is closed they receive the zero, so they know when they have to exit
