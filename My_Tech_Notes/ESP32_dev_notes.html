.. Mailboxes

A mailbox allows different tasks to exchange data. A mailbox is a queue of size one.
  • It is created as a queue of size ONE
  • To write to the mailbox, xQueueOverwrite() must be used.
  • To read from the mailbox, erasing the read datum, xQueueReceive() can be used.
  • To read from the mailbox, not erasing the read datum, xQueuePeek() can be used.

.. Task Priorities

(130) FreeRTOS scheduling is totally based on priorities: the higher ready task executes.
A task executing at a given priority is pre-empted when another task at higher priority exters the ready state.
When there is no task to execute, the scheduler runs the idle task.

(131) 25 priority levels, from 0 to 24. Zero is the lowest urgency, 24 the maiximum.
Tasks at the same priority execute in Round Robin. When the slice expires, the CPU is given to the next task at same priority.
If no task is ready, the idle task is run (149).
When a higher priority task is ready, it is executed immediately (131).
For many applications, runs the tasks at priority 1. (150)
In ESP32, the following CPUs are present:

  • CPU 0: Protocol CPU
  • CPU 1: Application CPU
The task states are : Ready, Running, Blocked (waiting for some event to become Ready), Suspended (132).

.. Mutexes

(151) Semaphores are prone to the priority inversion problem.
A mutex is created in given state, unlike semaphores, that are created in taken state (154).
Mutexes are created with a specific function, then they are used with semaphore take and give.
Recursive mutexes are supported.(164).

.. Semaphores

(97)

Binary semaphores

A binary semaphore has two states.
  • empty = not given = taken: an attempt to take a binary semaphore when it is empty will block
  • full = given = not taken
Here, the analogy is with a queue with a depth of one, either full or empty (97).
In FreeRTOS semaphores are created empty.

.. Interrupts

(166) Interrupt Service Routine (ISR).
  • A separate ISR stack exists, used by all ISR routines. Better to use small amount of stack.
    Check the ISR stack size in the menuconfig.
  • ISR handlers must be reentrant, short, they must not call blocking functions
  • ISR(s) have priorities, a high priority ISR blocks a lower priority ISR (166)
Reentrant functions: a function is reentrant if it can be invoked multiple times without corrupting the outcome of prior calls in progress.
(167) A reentrant function only uses its passed parameters and has no side-effect.
On the ESP32, an interrupt service routine is declared as: 
  void IRAM_ATTR myIsr()
  {
    /* ... */
  }
It means that the ISR must be placed in the IRAM. On the ESP32 there is approximately 128kB of IRAM. Some of it is preallocated.(169).

.. Task Events

(203) In FreeRTOS, each task has a built-in 32-bit notification value, initialized to zero when the task is created.

Task events do not use additional RAM, since the notification value is built-in in every task.
NOTE: there are restrictions (203):

  • It is not possible to send a notification to an ISR
  • Notification events cannot be queued
  • The notifying task cannot block waiting that the event is received by the receiving task

Platform IO: Development

The upload and the monitor step use the USB, by default it can only be accessed by the root user, to allow access to every user: 
  sudo chmod 666 /dev/ttyUSB0
Note that in Platform IO, the proper USB serial speed must be set. For the TTYGO Camera, set in the platform.ini file: 
  monitor_port = /dev/ttyACM0
  monitor_speed = 115200
Remember to set the permissions to the pseudo file /dev/ttyUSB0 or the one to access the USB, by default it can only be accessed by the root user. E.g. sudo chmod 666 /dev/ttyACM0 Other boards use: 
  monitor_port = /dev/ttyUSB0
  monitor_speed = 115200
Note: Platform I/O is located, for example, under: 
  /home/minguzzi/.platformio/penv/bin/pio

The IDF is located under: 
  /home/minguzzi/.platformio/packages/framework-espidf

Platform IO: build, run, etc

Suppose that the platformio.ini file contains: 
  [env:esp32dev]
  platform = espressif32
  board = esp-wrover-kit
  framework = espidf
  [...]
The environment is called esp32dev.

Note In order to build a project, using the cli, the command is: 

  platformio run --environment poc_test_esp32
	platformio run --environment esp-wrover-kit
	platformio run --environment esp32dev
In order to build, upload and monitor a project, using the cli, the command is: 
  platformio run --target upload --target monitor --environment poc_test_esp32  
  platformio run --target upload --target monitor --environment esp32dev
  platformio run --target upload --target monitor --upload-port /dev/ttyUSB0 --environment esp-wrover-kit

. Notes from the ESP32-WROVER datasheet Version 2.2, 2019

  • ESP32-WROVER : 4MB Flash, 8MB PSRAM Pseudo static RAM.
  • Sleep current is 5 microA.
  • FreeRTOS with LwIP
  • After reset release, strapping bits behave as normal function pins. GPIO,2,5; MTDI, MTDO
  • Peripherals, see chapter 4, page 14.
  • Source current 40mA, 20mA typical

. Notes from the ESP32 Technical Reference Manual Version 4.7, 2022

  • The CPUs are named PRO (protocol) and APP (application)
  • Little endian
  • Peripherals are mapped to memory
  • Reset and Clock(39): none of the reset types below clears the RAM
    • CPU reset:
    • Core reset:
    • System reset
  • IO_MUX and GPIO
    • GPIO pads 34-39 are input-only (45)
    • Reset configurations: each pad has a default configuration after reset (57)
      • 0: IE=0 input disabled
      • 1: IE=1 input enabled
      • 2: IE=1 WPD input enabled with pull down (WPD)
      • 3: IE=1 WPU input enabled with pull up (WPU)
      • GPIO12,13 by default are enabled, WPD
      • GPIO14,15 by default are enabled, WPU
