. Asynchronous Python (asyncio)

Book : Python Concurrency with asyncio. Up to page 146

Concurrency: more than one task at the same time.
Asynchronous: a task can run in background, the main is notified when the background task is finished. Asynchio: support for coreoutines and asynchronous programming. Single threaded event loop. STEL.

CPU-bound: the code would execute faster with a faster CPU.
I/O bound: the code would execute faster with a better device, e.g. network card.

Threads use the address space of the process that created them.
Concurrency can be achieved by multithreading and multiprocessing.
In Python multithreading is only useful for I/O bound, because of the global interpreter lock.

Asyncio: we execute coroutines, when an I/O operation is executed, the current curoutine is stopped, but other Python code can execute.
CPU-bound code must use separate processes to execute concurrently.
Asyncio saves time when I/O bounds operations are executed concurrently.
Do not call blocking I/O functions inside a coroutine, e.g.time.sleep(), requests.
You need to use a library that supports coroutines and uses non-blocking calls.

. Asynchronous HTTP (aioHTTP)

Web requests employ the concept of session. A session is like an open browser, that stores cookies.
Within a session, many connection can be pooled.
The session object has methods to execute web requests, like GET, PUT, POST.
Create the ClientSession with the async with syntax.

. Terms and acronyms

  • Awaitable: an object that can be used in an await expression.
  • Concurency : things happen at the same time. Switch between tasks is concurrent behavior.
    A baker can prepare a cake, while it is in the owen, he can do something else. But the cook does one thing at a time.
    In a single core CPU, the application can use preemptive multitasking to switch.
    Concurrency does not imply parallelism.
  • Coroutine in asyncio: a regular Python function.
    When we call a coroutine, it is not executed; a coroutine object is created.
    async.run() is the entry point to an asyncio application.
    await pauses the current coroutine to let other tasks run. It is followed by an awaitable object.
  • Event Loop: in asyncio the event loop keeps a task queue instead of a message queue.
  • Future : we can await on a future. It is an awaitable.
  • Global Interpreter Lock the Python interpreter can only execute one bytecode at a time.
    We can start multiple threads, but the interpreter only runs a process bytecode at a time, even with multicore GPU.
    There can be an executing thread per process.
    The GIL is released upon an I/O operation, so I/O-bound tasks can be made parallel with multithreading.
    This is true in CPython, which is the reference Python implementation.
  • Multitasking :
    • Cooperative : a task decides when to yield to another task.
      Less resource intensive than preempitive, no context switch.
    • Preempitive : the OS switches between tasks
  • Parallelism : thing actually occur at the same time. In the example: there are two cooks working at the same time.
    Needs a multi core CPU.
    Parallelism implies concurrency.
  • Process
  • Task in asyncio: a wrapper around a coroutine. Tasks are paused during an I/O operation.
    A task is an awaitable.
  • Thread : a lightweight process. All threads of the same process share the same address space- A process has a main thread and additional worker or background threads.
    A task can be cancelled only if it is awaiting on some operation, otherwise it runs to completion.
    It is possible to run a task with asyncio.shield(longTask) to prevent it from being shielded.
