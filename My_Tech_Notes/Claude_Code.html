Claude Code Project Setup

Claude Code is an agent harness wrapping around an LLM, any model.
Claude Code can be configured at two levels:
  • Agent layer: providing information to the agent layer about how to do things amd what it can do: CLAUDE.md, Skills, Subagents (for repeatable tasks), MCP
  • Harness layer: settings, hooks, plugins

Scope priority and file location

Scopes:
  • Managed: applies to all organization users in organization accounts .
    Higher priority
  • CLI scope: can exert temporary overrides
  • Local: applies to the current project only
    File location is .claude/
  • Project: applies to all contributors of the project
    File location is: the root of the project ROOT/CLAUDE.md, or in ROOT/.claude/CLAUDE.md.
    Under version control
  • User: the user settings, located in ${HOME}/.claude/
    Least priority, can be overridded by higher priority settings

Settings at higher pririty override those at less priority.
Priority, from bottom to top are: User, Project, Local, CLI, Managed

CLAUDE.md and rules: project level instructions

The command /init inspect the content in the project and creates a CLAUDE.md file.
In CLAUDE.md, use @ to import additional context.
CLAUDE.md can be updated by the agent itself. In CLAUDE.md:
  • Use markdown to create semantic structure
  • Keep it under 200 lines
  • Write direct, precise, unambiguous instructions

Subagents

Claude Code Docs on Agents
Start every task with the plan agent. /plan . Plan is a subagent that is invoked directly.
Each subagent runs in its own context window with a custom system prompt, specific tool access, and independent permissions. When the agent is finished, it sends back to the super agent the main finds and the summary.

/agents to list the available agents. Manage the available agents. Every subagent has its own context and tools. In most cases subagents are called by other agents.

Agents can run as:
  • Subagents: each subagent run in a single sessio and reports back to the main agent (default)
  • Agent Teams: each teammate is a separate Claude code instance.They work in parallel and coordinate before reporting back to the main agent.
Best practices:
  • Build your own agent for repetitive tasks
  • Avoid coflict by making each subagent task-specific
  • Build specialized agents for Skill, CLI and MCP tool use.

Code is an agentic coding tool.
Claude Code has several permission modes:
  • Default behavior: Claude asks for explicit permission before editing a file or running a shell command.
  • Auto-accept: Files are edited without asking, but commands still require approval.
  • Plan mode: Uses read-only tools to compile a plan of action before starting any work.

Plan mode

In plan mode, Claude does not edit, read-only tools. For planning complex code changes or executing a code review. For multi step implementations.

Context Management

Think of the context window as the amount of space Claude can hold in its memory. When you approach the CW limit, the context window is automatically compacted.

/compact : to compact the context window, it can lose details.

/clear clears the context window (CW)

/context all shows the CW detail

A vague prompt might seem smaller, but it actually costs more context in the long run. Without clear instructions, Claude is forced to explore your codebase more and do its own reasoning — which takes up far more context space than a detailed prompt would.

Code review

Before you push a PR, ask Claude to use a subagent to review your changes. The subagent runs in its own context window with fresh eyes — it doesn't carry the bias of the main agent that just spent the session writing the code.

Skills

Folders of instructions, scripts and resources. The Skill description allows Claude to decide whether to use the tool.

A Skill has a name and description loaded into context, and Claude only loads the full skill contents when it determines it needs to use it.

Store skills: personal skills in ${HOME}/.claude/skills
There are project skills, in the .claude/skills under the project root directory.
Skills load on demand when they match your request.
Claude do not need to call skills explicitly, it applies when the description matches the situation (the prompt).
Skills are for specialized knowledge that applies to specific tasks. Code review

MCP

Model Context Protocol. Context can live elsewhere: databases, apps, etc.
MCP via stdio if local, via HTTP if the MCP server is remote.
Stdio servers are for local processes that run on your machine.
MCP servers add tool definitions to your context window — even when you're not actively using them. If you have a lot of servers configured, this eats into your available context. Run /mcp to see what's connected and disable anything you're not actively using.

Hooks

Hooks are deterministic, MCP and skills are not.
You can tell CLAUDE.ms to run e.g. a code formatter after every edit of your file, bot sometimes , it won't
Example: autoformatting after edit.
  • PreToolUse — runs before a tool call
  • PostToolUse — runs after a tool call completes
  • UserPromptSubmit — runs when you submit a prompt, before Claude processes it
  • Stop — runs when Claude finishes responding
  • Notification — runs when Claude sends a notification
