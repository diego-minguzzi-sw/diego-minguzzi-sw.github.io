.1 Introduction

This document describes a set of proposed coding guidelines.
The guidelines are geared towards C++, but the naming rules and the general strategies can be applied to other languages as well.
This document tries to balance between an overly prescriptive set of rules with the lack of rules.
The guidelines try to make sure that a person can orient himself when reading the code of a colleague, and that a new developer involved in the project finds a common approach throughout the codebase, about cross-though decisions like the directory structure, error handling approach, etc. It is easier to participate in a project if everyone uses the same style.

.2 GENERAL STRATEGIES

.. The C++ standard

The preferred standard for the C++ language and the standard library is C++20.

.. Variable and type names

Do not use the Hungarian notation or any other name scheme where the identifier name depends on the data type, because the type can change in the future (e.g. an enumeration can turn into a class, etc.).
The name should reflect its intent/purpose, not its data type. The data type may change in the future, forcing the developer to rename all references. Moreover, intellisense does a better job at inferring data types.

Do not use abbreviations unless they are consistent all your code.
Do not worry about saving horizontal space as it is far more important to make your code immediately understandable by a new reader.

  • Type names (classes, structs, enumerations-enumerators) start with a capital letter and have a capital letter for each new word, without underscores.
    Examples: SportCar, UserParameter, etc.
  • Variable and function names are written in camel case, with the first letter lowercase, e.g. myFunction().
  • Constants and #define macros in all capital letters separated by underscore characters, e.g. MAX_SPEED.
  • File names and directory names should be all lowercase separated by underscores: app/hello_world.cpp
Do not construct identifiers using the name of the current project, because in the future the same code can be re-used again in a different project.
