Image = files and metadata.
The state of the container is the same as the state of the program running in the container.
When the program stops, the container is also stopped, but it is not yet removed.

Docker is not virtualization, it is containerization. Containers are an operating system feature.
Programs in the container interface directly with the Linux kernel of the host.
Running Docker means running both the Docker engine and the Docker CLI in user space. (6)

Think of a Docker container as a physical shipping container the container stores the application and its dependencies.(7)

The component that acts as the container is the image. IMAGE: a bundled snapshot of all the files that should be available to a program inside the container.

Multiple containers can be created from the same image: they do not share the filesystem. Docker runs natively in Linux, there is a virtual machine for Windows and MacOS.
Software running in a container is more secure.

Chapter 4: Working with storage

Linux unifies all storage into a single tree. Storage devices area attached to mount points.
Every container has a MNT namespace and a unique file tree root, but other storage can be mounted into containers:
  • Bind mounts: (64) a container file is physically a file in the host filesystem
  • In-memory storage: in the container memory
  • Volume: example: /var/logs in the container is mapped to a directory of the host
All the point points are created using the --mount flag on the docker run and docker create commands.

Bind mounts

Bind mounts: it attaches a specific location of the host filesystem to a specifi point of the container file tree.
Example of creation of a bind mount: docker run -d --name diaweb --mount type=bind,src=${CONF_SRC},dst=${CONF_DST} nginx:latest
In case a file exists in the container, the bind overrides the content of that file with what is provided by the host. The mount can be read-only so the container cannot modify the file:
docker run -d --name diaweb --mount type=bind,src=${CONF_SRC},dst=${CONF_DST},readonly=true nginx:latest
Source is the host, destination is the container.
The file provided by the container overrised the file contained in the container filesystem.
Bind mounts are appropriate for workstations, machines with specialized concerns, systems combined with more traditional configuratoin tooling. It is better to avoid them in generalized platforms or hardware pools (67).

Example fo sharing a file using bind mount.
Bind: the source is part of the host filesystem, the destination is part of the container filesystem.

echo "All commands paths are relative to the working directory."
export LOG_SRC=$(pwd)/web-logs-example
echo LOG_SRC=${LOG_SRC}

mkdir -vp ${LOG_SRC}
docker run --name plath -d --mount type=bind,src=${LOG_SRC},dst=/data dockerinaction/ch4_writer_a
docker run --rm --mount type=bind,src=${LOG_SRC},dst=/data alpine:latest head /data/logA
Tmp filesystem : the tmp filesystem is mounted to the container filesystem and it writes in memory. Example: 
docker run --rm --mount type=tmpfs,dst=/tmp --entrypoint mount alpine:latest -v
The command below limits the tmp filesystem size to 10MB and make it make it not readable to other in-container users. 
docker run --rm --mount type=tmpfs,dst=/tmp,tmpfs-size=10M,tmpfs-mode=1770 --entrypoint mount alpine:latest -v
Hint: entrypoint is the default command to execute at runtime: 
docker run --rm --mount type=tmpfs,dst=/tmp --entrypoint /bin/bash alpine:latest

Docker Volumes

: Docker volumes are named filesystem trees managed by Docker. They can be implemented with disk storage on the host filesystem.
To create docker volumes: 
docker volume create \
       --driver local --label example=location \
       location-example
Uses the local plugin, named location-example. To inspect the volume: 
docker volume inspect --format "{{json .Mountpoint}}" location-example
Volumes are created, not associated to any container
A volume has name, a set of key-value pairs, volumes can be shared among containers. When you are finished with a volume, Docker can clean things up (69).
The data contained in the volume can have a scope or life cycle that is independent from a single container (70).
  • Images are used to distribute static content
  • Volumes are used to hold dynamic data specializations
There is the concept of polymorphic behavior
Volumes inject behavior into containers without modifying the image.

Chapter 5: Single host networking

  • Protocol: with respect to communication and networking is a sort of language.
  • Interfaces A network interface has an address and represents a location.
    Think of it like a mailbox: all messages to the recipients at that location are delivered to the same mailbox. A mailbox has a postal address, a network interface has an IP address.
    Computers have an ethernet interface and a loopback interface.
  • The port identifies the sender or the recipient. The port concept is part of the TCP and UDP level.
(83) Relevant networks are:
  • the network that the computer is attached to
  • the virtual network that Docker creates to connect all running containers to the network that the computer is attached to.
The Docker Network acts as a bridge. A bridge selectively forwards traffic between the connected networks, based on another type of network address (83).
The bridge creates the illusion that all hosts of the networks connected to the bridges are part of the same network.

  • A container gets a unique IP address in the Docker virtual network
By default three networks:
  • bridge: intercontainer connectivity
  • host: the container has direct access to all host interfaces
  • none: containers attached to none do not have any network connectivity.
Network scope can be:
  • local: the network is constrained to the machine where the network exists
  • global: exists in every node of the cluster but without route between them
  • swarm : seamlessly span all of the host participating in a Docker swarm
Using the default bridge network is not recommended (84).

To create your own bridge network: the Docker bridge, a customizable network topology. The resulting network is local to the machine where Docker is running, it creates a route between the containers and the network where the host is attached.
Each container has a virtual interface. All containers interfaces are connected to the Docker bridge interface (named e.g. docker0. In turn, the Docker bridge is connected to a logical host interface, which is connected to the physical network interface.

To build a network called user-network, issue the command: 

docker network create \
        --driver bridge \
        --label project=dockerinaction \
        --label chapter=5 \
        --attachable \
        --scope local \
        --subnet 10.0.42.0/24 \
        --ip-range 10.0.42.128/25 \
        user-network

The docker commit adds a new layer to the image. It saves a set of attributes: the env variables, the working directory, the exposed ports, volumes the container entrypoint, the commands and arguments (130).
Every time files are added, modified or deleted, those modifications become a new layer to the image.
(134) A commit action saves the changes to the top layer in an identifiable way; the layer has a parent that is the payer below it.
A collection of all layers exists: an image is a sequence of layers, from leaf to its parents until the root. The root is the starting layer.(135) A commit produces a new image ID, something like: e8114fb60a8ed9ac914d7999a644ba758b50a32771aca3979aba6ffe757945c0
