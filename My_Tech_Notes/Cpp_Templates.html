Chp 01: Function Templates

The process of replacing template parameters with concrete types is called instantiation (40). It results in an instance of a template.
Templates are compiled in two phases: definition time: the syntax is checked, everything that does not depend in template parameters is checked.
At instantiation time the template is checked against the template parameters (41).
Overloading function templates: (51) the overload resolution process prefers the nontemplate over the function generated from the template. The syntax: 
::max<>( 7, 42); // Forces the use of the template.

Automatic type conversion is not considered for deduced template parameters, but it is considered for ordinary functions (52).
In templates, pass arguments by value (57).
In general, function templates do not have to be declared with inline (57). The exception to this rule are full specializations for specific types (57).

Chp 02: Class Templates

Suppose that the class template is Stack<T>code>. The Type of the class is Stack<T>code>.
You have to use the class type Stack<T>code> whenever you use the type of the class in a declaration, except cases where the template parameters can be deduced.
For example when implementing the members (64).
Inside the class use simply the class name, so Stack.
(66) Code is instantiated only for template functions that are called. So, only those functions are checked (68).
(71) Specialization of Class Templates. You can specialize a class template for certain template arguments.
Similar to the overloading of function templates, specializing class templates allows you to optimize implementations for certain types or to fix a misbehavior of certain types for an instantiation of the class template.
However, if you specialize a class template, you must also specialize all member functions.
Suppose we define: 
using IntStack= Stack<int> ;
They become two interchangeable notations for the same type (79).

Moreover, an using declaration can be parameterized (80).
See Type Traits suffix_t (81).
