6.2 One definition rule

No translation unit shall contain more than one definition of any variable, function, class type, enumeration type, or template.
[42] Exactly one definition of a class is required in a translation unit if the class is used in a way that requires the class type to be complete. The class does not need to be complete if it used in pointer formation.

6.3 Scope

6.3.2 Point of declaration

The point of declaration for a name is immediately after its complete declarator and before its initializer (if any). A name from an outer scope remains visible up to the point of declaration of the name that hides it. 
unsigned char x = 12;
{ unsigned char x = x; }
The second x is initialized to its own undeterminate value. The point of declaration for a class or class template first declared by a class-specifier is immediately after the identifier or simple-template-id (if any) in its class-head. The point of declaration for an enumeration is immediately after the identifier (if any) in either its enum-specifier or its first opaque-enum-declaration, whichever comes first.

6.3.3 Block scope

[46] A name declared in a block has block scope: it potential scope begins at the end of the declaration and ends at the end of the block. Names declared in the init-statement, the for-range-declaration, and in the condition of if, while, for, and switch statements are local to the if, while, for, or switch statement.

6.3.4 Namespace scope

[47] Entities declares in a namespace body have potential scope starting from the declaration to the end namespace.

Pointers and consts

[187] When using a pointer, two objects are involved: the pointer itself and the object pointed to.
Pre-fixing a declaration of a pointer with const makes the object, but not the pointer, a constant.
To declare a pointer itself, rather than the object pointed to, to be a constant, we use the declarator operator *const instead of plain * . 
const char* pc = s; // pointer to constant
char *const cp = s; // constant pointer
The declarator operator that makes a pointer constant is *const. There is no const* declarator operator, so a const appearing before the * is taken to be part of the base type.
For example: 
char *const cp; // const pointer to char

char const* pc; // pointer to const char
const char* pc2;// pointer to const char
So, char const* is the same type as const char* .
Some people find it helpful to read such declarations right-to-left, for example, cp is a const pointer to a char and pc2 is a pointer to a char const.

Optimizing Dynamic variables

Storage duration

  • [108] Variables with static storage duration live in memory reserved by the compiler. Each global static variable is constructed before execution enters main() and destroyed after execution leaves main().
    There is no runtime cost to create the storage for static variables. However, the storage is not available for reuse.
    Static variables are thus appropriate for data that will be used for the whole life of the program.
  • [109] Thread-local storage duration Thread-local variables are constructed at thread entry and destroyed at thread exit; their lifetime is the same as the lifetime of the thread. Each thread has its own separate copy of these variables.
  • Automatic Variables: there is no runtime cost to allocate the storage used by automatic variables.

Uniform initialization

If a class has an initializer list constructor, it takes the precedence over the other constructor for that class.

In C++17, the form below is used for initializer lists with auto:

Non static class members initialization

In C++17, it is possible to initialize a constant member with "default member initialization", and also any member whose initializer do not depend on a value passed to the constructor.
Prefer the initializer list and the default member initialization.
The order in which non static data members are initialized is the same as the order in which they are declared in the class definition / declaration.

The order in which non static data members are destroyed is the reverse of the order of construction.

If not initialized in the initializer list, non static members are initialized via their default constructor and then, when assigned in the constructor body, the assignment operator is invoked.
If a data member is initialized both with the default member initialization and in the initializer list, the latter takes the precedence and the default member is discarded.
