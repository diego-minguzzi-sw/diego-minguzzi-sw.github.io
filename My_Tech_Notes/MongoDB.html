    .. Replica set

    Replica set: multiple MongoDB instances providing access to the same dataset.
    Instances have different roles.
    There must be at least three instances in a replica set.
    • One instance is elected to be the Primary: it receives all write operations
    • Secondaries replicate the write operations asynchronously, one of the remaining will be elected as Primary. It can do if it gets more than half of the DB nodes votes. So, at the beginning, there must be no at least three nodes.
    • Choose an uneven number of voting replica set members.

    .. Working with MongoDB

    ... The Document Model

    MongoDB natively works with Json documents.
    Key-Value pairs. Keys must be strings. Values can be string, numbers, booleans, arrays, other Json objects.
    MongoDB uses a binary encoded serialization of Json called BSON.
    BSON is designed to be lightweight, traversable and efficient.
    BSON can store binary data as images, timestamps and longs, etc.

    Namespaces, collections, documents

    So far, the MongoDB deployment is composed of e.g. three replicas.
    Inside MongoDB, data is organized into databases. There is a database deployment, inside it there can be multiple databases.

    ... Indexes

    If you have no index associated with the document, the query have to search every document in the collection.
    This is called collecton scan. Not efficient.
    An index provides an organized way to look up data by storing a subset of the data with pointers to the location of the full records.

    Queries that can be answered only by looking at the index are called covered queries. Performance in access and update.

    Indexes have a cost: 10% write overhead.
    Different kind of indexes in MongoDB:

    • Single field indexes
    • Partial indexes
    • Compound: combination of fields
    • Multi key indexes
    • Text indexes
    • Wildcard indexes
    • Geospatial indexes: geometric indexes, 2D, geostack indexes
    • Hashed indexes

    CRUD operations

    • Durability: acknowledged writes are permanently stored in the DB, even if part of it becomes temporarly unavailable.
      In MongoDB, this is specified by the writeConcern property:
      • High durabilty: slower writes
      • Low durability: faster writes
            # wtimeout: the write operation will block for at most 100ms.
      # j: true: it must write to disk, not just in memory, to acknowledge the write.
      # w: majority:  the majority of the instances must acknowledge the write before saying that the write is completed.
      db.records.insertOne( {name:"Alessandro",surname:"Manzoni"},
                            { w:"majority", j:"true", wtimeout:100 } )
      w: majority is the default.
      Which write concern? If you do not want to lose data, w: majority, data survives failovers.
    • Consistency and Availability: in some cases find() and findOne() must retrieve data that is majority committed.
      Otherwise, it is enough to read from the primary. This is specified by the readConcern property.
      Reading from the secondary is fine for analytics data.

    Transactions

    An operator on a single document is atomic.
    However, if a client issues an operation on multiple documents, and another client issues a query, this is a race condition.

    Transactions guarantee atomicity or reads an writes to multiple documents.

    • Either all or none write happends.
    • Read returns all documents in the state when the read begins.
      use blog
  session= db.getMongo().startSession({ readPreference: { mode: "primary" } })
  session.startTransaction()

  # Retrieves the database, and performs the operations as above.
  session.getDatabase("blog").authors.updateMany({},{ $set:{ message: "Transaction occurred."}})
  session.commitTransaction()
    Word of Warning:
    • Use transactions when you absolutely need them: otherwise performance degradation
    • If you need transactions more than a few times, check the data model: update operations should update single documents, that way they are atomic.
