Sessions and handoff A session is the unit of work with an agent in Visual Studio Code. It includes the sequence of prompts and responses, relevant context, and any files or resources associated with the task.
Start a new session when you change topics to help the AI provide more relevant responses.

A session can contain more than one chat. Each chat is an independent conversation with its own history, title, status, and agent or model selection, but all chats in a session share the same workspace and code isolation. A new chat starts blank and doesn't inherit the conversation history of the other chats in the session. Handoff changes the session target from one harness to another and carries the full conversation history and context with it. Best Practices Best Practices

Notes on GitHub Copilot with the VS Code Extension

This file contains notes on the Copilot extension for Visual Code, in particular when used in the Edit mode to suggest and autocomplete the code, in a C++ project.

The VS Code Copilot also includes an agent mode.
However, it is an interactive editing mode, different from the Copilot coding agent that autonomously executes a tasks and creates the related pull requests.
The Copilot coding agent is only available from the GitHub website with the proper subscription.

Copilot Suggestions

  • Inline Suggestions: for example, completing the current line or generating an entire block of code. Inline suggestions appear as dimmed ghost text.
    • Tab to accept
    • Ctrl+Right to partially accept
  • Suggestions can also be generated from code comments.
  • Next Edit Suggestions (NES): Copilot suggests where to edit next. Indicated by a blue arrow in the gutter. NES can be disabled or shown collapsed.

Settings Examples

Sometimes Copilot suggests its own completion before knowing what the added code is, and it also interferes with the TAB that is used to indent code.
Solutions: delay suggestions or trigger them using a shortcut.

Enable Inline Suggestions, but Add a Delay before Copilot starts suggesting

To add a delay, insert the following JSON to the bottom of your settings.json file:

"editor.inlineSuggest.enabled": true,
"editor.inlineSuggest.minShowDelay": 2500,
"github.copilot.nextEditSuggestions.enabled": true,
"editor.inlineSuggest.edits.showCollapsed": false

Disable Inline Suggestions, trigger by shurtcut

Add the following JSON to the bottom of your settings.json file:

"editor.inlineSuggest.enabled": false,
"github.copilot.nextEditSuggestions.enabled": true,
"editor.inlineSuggest.edits.showCollapsed": false

Keyboard shortcut: You can still trigger inline suggestions using Alt + \\

This works with Visual Studio Code version 104 and above. Note that VS Code may modify settings when extensions are added or updated.

Copilot Instructions

You can add a file named .github/copilot-instructions.md to the root directory of your Visual Studio Code project. Copilot will use it as context for every request.

If used, the file appears as context in the Chat tab. It can be disabled if needed.

Common sections to include in Copilot instructions:

  • Overview
  • Design Patterns
  • Coding Standards
  • Coding Guidelines
  • Logging
  • Folder Structure
  • Final Tips

Link to Docs

You can also auto-generate Copilot instructions as a first draft and then manually refine them. In Chat mode, go to:
Configure Chat → Generate Instructions

Appendix: Example of a copilot-instructions.md file for a C++ project

  
# Github Copilot Instructions for the project: automation-gateway-scanner

This instructions customize the generation of C++ code.
Generate a completion only if the generated code is formatted the same way as the surrounding code.

## Overview
This project implements a layer of an automation system.
The Automation Gateway Scanner manages a set of Automation Elements.
They have a common interface, but they are also specialized.
Automation Elements receive commands from upper layers and notify events.

## Design patterns
Common design patterns are:
- publisher subscriber
- factory method

## Coding standards
  - C++ code uses the C++20 standards: explicit constructors, uniform initialization, constructor initialization List
  - in C++ classes, the public part comes before the protected (if it exists), then the private part
  - indent using 2 spaces
  - curly braces of methods and loops occupy their own line
  - align curly braces vertically in all constructs except namespaces, example:
```cpp
    if (::robot_control::notOk(resCode))
    {
      return resCode;
    }
```
  - use 'auto' to declare variables, whenever possible. Examples:
```cpp
    const auto& posBase= cartPoseBase.position();
    auto myString= ::std::string{"Hello world."};
```
  - to compare a constant to a variable for equality, write the constant, the == sign and then the variable.
  - local variables in camelCase, with the first letter lowercase
  - member variables in camel case, with leading underscore, and the next letter lowercase example: ```cpp _virtualRobot```
  - functions and methods in camel case, first letter lowercase: ```cpp myFunction()```
  - getter methods names do not start with get.
  - Class constructors other than: default, copy and move constructor, must be marked as explicit.
  - all data types in CamelCase, with the first letter uppercase: classes, structs, enums, using, typedefs, etc., examples: SportCar, UserParameter
  - template arguments, preprocessor macros and defines in UPPER_SNAKE_CASE
  - file names should be all lowercase separated by underscores.
  - namespaces in snakecase, all lowercase.
  - use full qualified names, with namespaces. Add leading :: to the namespace, example  ```cpp ::std::string```
  - each line should be at most 100 characters long. If the arguments do not all fit on one line, they should be broken up onto multiple lines, with each subsequent line aligned with the first argument. Example:
```cpp
    _ptrSmartCamera->setLight(lightControlMode,
                              ::robot_control::MinLightIntensity,
                              actionId);
```

  - try to use the if statement with initializer. Example:
```cpp
    if (auto resCode= robotControl.getServoState( servoState); ::robot_control::notOk(resCode))
    {
      TRACE_ERR2("getServoState:", ::robot_control::to_string(resCode));
      return resCode;
    }
```

## Coding Guidelines
- Most methods of classes derived from Automation Element return an enumerator ```cpp ::gw_comm::autom_elements::ErrorCode```
- It is possible to check if the return error code is success or failure using the functions ```cpp ::gw_comm::autom_elements::isErrorCodeOk()``` and ```cpp ::gw_comm::autom_elements::isErrorCodeNotOk()```
- Most classes and enumeration have a ```cpp to_string()``` function in the same namespace, that return a string representation of a class object. Example:
```cpp

  if ( auto errCode= aMethod(); ::gw_comm::autom_elements::isErrorCodeNotOk( errCode))
  {
    LOG_ERROR("aMethod failed: {}",::gw_comm::autom_elements::to_string(errCode));
    return errCode;
  }
```

## Logging
  - Custom macros are used to issue log messages of a given severity, from least critical to most critical: LOG_TRACE(), LOG_DEBUG(), LOG_WARN(), LOG_ERROR(), LOG_CRITICAL()

## Folder Structure
The directory `sources/` is where relevant source code is stored.
The most important code is stored under `sources/libs/`
Under `sources/libs/`, each directory contains the code to compile a specific library.
Example: `sources/libs/robot_autom_elements/` contains the code to build the library RobotAutomElements.
Each library directory contains the subdirectories:
  - `include` : the header files with the interface of the library
  - `src` : the code that implements the library
  - `test` : the unit tests, developed using Catch2

Ignore the following directories, they do not contain relevant maintained source code.
They are:
  - `adapter/`
  - `build/`
  - `cmake/`
  - `debian/`
  - `docker/`
  - `installed_packages/`
  - `rta-eip/`
  - `script/`
  - `target/`


## Key Files & Directories
  - `automation-gateway-common/include/gateway-common/field_configuration_entities/robot/defs.h`: Enum and data model definitions.
  - `automation-gateway-common/include/gateway-common/field_configuration_entities/robot/json_serdes.h`: Enum conversions and serialization.
  - `automation-gateway-common/include/gateway-common/autom_elements/error_code.h` Error codes returned by most Automation Elements


## Final tips
  - Keep comments concise and meaningful.
  - Avoid unused includes and redundant code.
